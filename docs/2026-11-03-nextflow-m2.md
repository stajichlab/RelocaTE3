## Fixed (dba6760, 2026-11-03 14:10): container profiles crashed at start

Fix: nf-schema 2.7.3 → 3.0.0; minimum Nextflow 25.10 → 26.04 (nf-schema
3.0.0 needs ≥ 26.04.0; pixi `nf` env has 26.10.4, cluster modules
26.04.2–26.04.6; `nextflow/25.10.4` now refused at plugin load).
3.0.0 migration guide items applied:
- `paramsSummaryLog()` without the `workflow` argument.
- Help only via `paramsHelp()`: called in `main.nf` when `params.help` is
  set, then `exit(0)`, before `validateParameters()`. `--help` exits 0
  without input/genome/outdir; `--help <param>` uses the `parameter:` option.
  This also fixes the M1 `--help` exit-1 issue.
- `validation.help.enabled` removed (not a 3.0.0 option).
- `failUnrecognisedParams`/`failUnrecognisedHeaders`: never used here.
- `help` added as a hidden schema param (default false) and to `params`, so
  the schema/config param tests stay equal. nf-schema ignores `help` in
  validation by default.

Tests: `tests/nextflow_startup_test.py` (5): `-preview` under
`test,apptainer|docker|singularity` exits 0 and logs the image; `--help` and
`--help te_aligner` exit 0. Red on 2.7.3 ("Cannot cast object
'ghcr.io/stajichlab/relocate3:dev'", "Missing required parameter(s)"),
green on 3.0.0. pytest 473, nf-test 30, lint 18 files clean.
Parity gate (pixi): job 31638655, **RESULT: PASS** (33 files in both, 28
identical, 0 differing; 7 tasks, 0 cached; nf-schema 3.0.0).

Cosmetic, upstream: nf-schema 3.0.0 `paramsHelp()` drops the lines of its
built-in `--help`/`--helpFull`/`--showHidden` entries but not their wrapped
continuation lines, so two description fragments appear at the top of the
help output.

Original report:

Found in Task 5 (job 31638101, `-profile hpcc,apptainer -preview`):

```
ERROR ~ Cannot cast object 'ghcr.io/stajichlab/relocate3:pr-63' with class 'java.lang.String' to class 'java.util.Map'
 -- Check script 'main.nf' at line: 19   (log.info(paramsSummaryLog(workflow)))
```

- Cause: nf-schema 2.7.3 `paramsSummaryLog` does
  `Map containers = paramsMap['Core Nextflow options']?.get('container')`.
  With one global `process.container` (our container profiles),
  `workflow.container` is a String, so the cast fails. Same code in 2.8.0;
  fixed in 3.0.0 (`if (containers in Map)`), which also removes the
  positional argument of `paramsSummaryLog()`.
- Affects every container run: Task 6 parity, Task 7 real rice, and CI's
  pipeline-container job (docker). `-profile test,pixi` and `hpcc,pixi` work:
  no container is set.
- Not fixed here (outside Task 5). Needs a decision: upgrade nf-schema to 3.x
  (check its Nextflow minimum), or set the container per process
  (`withName: '.*'`, which makes `workflow.container` a Map). Add a test that
  runs `main.nf` with a container profile (e.g. `-preview`) so it stays
  fixed.

### Decisions

- **One config.** Every calling setting comes from `[relocate3]` via
  `--print-params`: `aligner`→`te_aligner`, `insert_size`→`size`,
  `characterize`→`genotype`, and the rest by name. Settings
  `run_relocate3.sh` does not pass stay at the pipeline defaults, which equal
  run-all's.
- **Relative config paths** (`te_library = ../../tests/...`) resolve against
  the config directory, as `run_relocate3.sh` does by `cd`-ing there.
- **Layout per OUTDIR:** `OUTDIR/` results, `samplesheet.csv`,
  `container_tag.txt`; `OUTDIR.nextflow/` launch dir (own `.nextflow/history`);
  `OUTDIR.nextflow/work/` work dir. A bare `-resume` resumes the last run in
  the launch dir's history; a shared launch dir (e.g. repo root, also used by
  parity runs) could resume the wrong session.
- **Reruns:** rerunning into the same OUTDIR is intended (`-resume`). Refused:
  an OUTDIR made with another tag, or a sheet that no longer matches the config.
- **rc2 file set:** 31 files per sample. No `genome_aln/<s>.reads.genome.bam`
  on either side: rc2 used `--genotype-bam`, and the pipeline skips
  ALIGN_READS for samples with a `genotype_bam`. (The plan said 33; that is
  Chr3 run-all without a genotype BAM.)
- **Indexes:** `compare_outputs.sh` skips `.bai` contents (they follow BAM
  bytes, which include `@PG`). The file-list step checks them, reported as
  `presence_only`.

### Watch in Phase B

- **Genome index:** the pipeline indexes its own copy of MSU_r7 (~374 Mb) in
  the work dir; the existing `.bwt`/`.mmi` next to the FASTA are not staged.
  `bwa index` + `minimap2 -d` run once (process_medium: 4 CPU, 8 GB; retried
  with more on exit 137/140).
- **Image pull:** done once on the head node into `NXF_APPTAINER_CACHEDIR`
  (`pullTimeout` 60 min). The head job loads `apptainer/1.5.3`; task jobs get
  PATH from it (SLURM exports the environment).
- **Memory:** TE_SEARCH is `process_high` (8 CPU, 8 GB, x attempt, 2 retries).
  rc2 ran with 64 GB; the chunked-trim fix put BLAT runs at ~3.4 GB, so 8 GB
  should hold. Check the trace for retries.
- **Threads:** rc2 used 16 threads per sample, the pipeline uses the label
  CPUs. bwa aln/sampe output should not depend on threads; investigate any
  difference before concluding anything.
- **-resume:** keyed on the launch dir (`OUTDIR.nextflow`). A new container
  tag means a new OUTDIR and a full rerun, by design.
