## Task 2: real-rice validation through the pipeline (2026-11-07)

### What changed
- `validation/real_rice/run_validation.sh --mode pipeline|run-all`, default
  `pipeline`.
  - Pipeline mode:
    1. Runs `run_pipeline.sh`'s `DRY_RUN=1` check: the inputs and the tag.
    2. Submits `run_pipeline.sh <tag> <outdir>` with `sbatch --wait`.
    3. Normalizes and compares on that outdir.
  - `--container-tag` (or `CONTAINER_TAG`) is required; there is no default.
    `--pipeline-outdir` defaults to `run_pipeline.sh`'s
    `results/nextflow-real-rice/<tag>`.
  - Run-all mode works as before.
  - New `--report-dir`. `DRY_RUN=1` prints every command (`+ ...`).
- `_config.py` honours `RELOCATE3_VALIDATION_OUTDIR` and
  `RELOCATE3_VALIDATION_REPORT_DIR`, which override `[paths].relocate3_outdir`
  and `report_dir`. A relative value is resolved against the cwd.
  `run_validation.sh` exports them, so the config is not edited.
- `validation/release/submit_real_rice.sh <ref> --container-tag <tag>` has
  pipeline mode as the default:
  1. A head job, `run_pipeline.sh`, writing to `clone/validation/real_rice/results`.
  2. A dependent report job, `run_validation.sh --mode pipeline --skip-run`.
  - `--mode run-all` keeps the array.
  - Mutable tags are refused.
  - `DRY_RUN=1` is supported.
- Tests: `tests/real_rice_validation_modes_test.py` (22 tests). Suite: 763
  passed.

### Decisions
- The outdir override uses environment variables read by `_config.py`, rather
  than a generated temp config. Every normalizer and compare script already
  goes through `load_config`, and the printed `relocate3_outdir:` line shows
  the value they will use.
- Pipeline mode waits with `sbatch --wait`, like run-all mode.
  `submit_real_rice.sh` chains a dependent report job, as before.
- Pipeline mode refuses `--force`, `--local`, and sample names unless
  `--skip-run` is given. The pipeline resumes into its outdir and runs the
  whole sheet.
