## Purpose

With BLAT, the TE search of one sample used to run as one long task (13 h for
riceTElib 30x). M4 spreads it over cluster jobs. Every output stays identical.

## Task 3: pipeline modules and wiring

Files:
- `modules/local/relocate3_te_split/`, `relocate3_te_search_chunk/`,
  `relocate3_te_merge_trim/` (each with a stub nf-test);
- `subworkflows/local/te_search_scatter.nf`;
- `subworkflows/local/one_sample.nf`;
- `conf/base.config`, `conf/modules.config`;
- `nextflow.config`, `nextflow_schema.json` (group `scatter_options`).

The scatter branch runs when `params.te_aligner == 'blat' && params.blat_scatter`.
Otherwise one `RELOCATE3_TE_SEARCH` task runs. Both branches emit
`te_containing`, `flanking` and `read_repeat`, so the steps downstream are
unchanged.

Decisions:
- **Grouping.** A sample's chunk FASTAs, both sides, are sorted by file name
  (`chunk.<id>.<side>.NNNNN.fa`: left before right, then by index). They are
  cut into consecutive groups of `blat_chunks_per_task` with `List.collate`,
  inside a `map`.
  - The groups depend only on the split, never on task timing, so `-resume`
    reuses every chunk task. `tests/nextflow_resume_test.py` checks this:
    everything is CACHED with 3 chunk tasks.
  - Groups may mix sides. Every group task stages `manifest.tsv`, which gives
    each chunk's mate.
- **Gathering.** The number of groups per sample is known after the split.
  The chunk BAMs are combined with that count, keyed with
  `groupKey(meta, n_groups)`, and passed to `groupTuple()`. A sample's merge
  therefore starts when its own last group finishes, not when every sample's
  groups do.
  - Then `key.getGroupTarget()` gives back the plain meta, and the BAMs are
    sorted by name. `te-merge-trim` orders them by the manifest anyway; the
    sort keeps the merge task's inputs stable for `-resume`.
- **Labels.**
  - TE_SPLIT: `process_single` (1 CPU, 4 GB, 4 h).
  - TE_SEARCH_CHUNK: new label `process_blat_chunk` (4 CPUs, 2 GB, 4 h;
    was 4 GB until the review fixes: the 30x trace peaked at 0.36 GB).
    `process_medium` (8 GB, 12 h) would only make the many small jobs wait
    longer in the queue.
  - TE_MERGE_TRIM: new label `process_merge_trim` (2 CPUs, 8 GB, 8 h; was
    `process_medium`, 4 CPUs, 12 h). The 30x trace: 3.2 GB peak, ~1.2 CPUs,
    32 min.
- **Zero reads.** TE_SPLIT's chunk output has `arity: '1..*'`. A sample with
  no reads therefore fails at the split instead of silently vanishing.
  `run-all` fails on such a sample too.
- **Params** (pipeline-only):
  - `blat_scatter` (default true);
  - `blat_chunks_per_task` (default 8; Task 6 tunes it);
  - `blat_chunk_reads` (hidden, default 200000). A pytest pins it to
    `aligners.BLAT_CHUNK_SEQS` and to `te-split`'s default.
- **Publishing.** TE_MERGE_TRIM is published like TE_SEARCH. Chunk files are
  not published. The 33-file per-sample nf-test assertion still holds.

Tests (red first, then green):

## Fix: `--<boolean> false` on the command line was true (2026-11-06)

**Found:** the 30x run job 31766412 with `--genotype false` still ran
ALIGN_READS (90 min wasted). The params summary printed `genotype : false`.

**Root cause.** Nextflow 26.04+ parses with the strict syntax parser, which
turns off the old type detection of command-line params
(docs.seqera.io/nextflow/migrations/25-10; strict parser default:
.../migrations/26-04). A probe on 26.10.4: `--flag false`, `--flag true` and
bare `--flag` all arrive as `java.lang.String`; `"false"` is true in Groovy.
nf-schema 3.0.0 casts only a temporary copy for validation, so validation and
the summary looked right.

**Effects (every pipeline commit since M1; locked Nextflow is 26.10.4 since
the first pipeline commit 5e3f478, so local `main` 583cd59 and M3 too):**

| CLI | effect before the fix |
|---|---|
| `--require_both_junctions false` | FIND_INSERTIONS still got `--require-both-junctions` (different calls) |
| `--excision false` | CHARACTERIZE got `--excision` (excision ON) |
| `--genotype false` | ALIGN_READS, CHARACTERIZE, COHORT still ran |
| `--skip_multiqc false` | MULTIQC and SAMPLE_STATS skipped |
| `--blat_scatter false` | still scattered |
| `--help false` | printed help and exited |

Not affected: `true` / bare flags, values from `nextflow.config`, profiles,
`-params-file` YAML/JSON (typed already), nf-test `params {}` blocks (why the
nf-tests missed it), and `relocaTE3` itself. No tagged release contains the
pipeline (v0.2.0rc2 has no `main.nf`).

**Fix.** Documented typed parameters (Nextflow >= 25.10,
docs.seqera.io/nextflow/typed-parameters): `main.nf` `params {}` block declares
the five booleans `Boolean`, defaults equal to `nextflow.config` (which still
holds them and overrides). Nextflow converts true/false (any case), bare flag =
true, and stops on any other word. `help` stays untyped (flag or param name);
`main.nf` treats `--help false` as no help. Lint clean with modules reading
`params.*` directly.

**Tests (red → green).**
- `tests/nextflow_boolean_params_test.py`: real `nextflow run` from a temp
  launch dir. Stub runs for task selection with `false` / `true` / bare;
  `-params-file` with `false`; `--genotype maybe` rejected; `--help false`.
  Two real tiny runs check `.command.sh` of FIND_INSERTIONS and CHARACTERIZE.
  Before the fix: 4 of 8 failed (false spelling, help false, both flag runs).
- `tests/nextflow_schema_test.py::test_every_boolean_param_is_typed_in_main_nf`:
  every schema boolean is typed in `main.nf` with the config's default.

**After:** pytest 714 passed (0 failed/errors/skipped); nf-test 51 passed;
