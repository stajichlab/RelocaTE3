## G_1 investigation (2026-10-26)

Question: why does RelocaTE3 have 1270 extra raw calls, almost all one-sided?

Answer: the real-rice harness, not the shipped pipeline. Three causes:

1. Different tiers compared. `normalize_relocate2_nonref.py` reads R2's
   filtered `ALL.all_nonref_insert.gff`; `normalize_relocate3_nonref.py` reads
   R3's unfiltered `ALL.mping.all_nonref_insert.txt`.
2. Different settings. R2's real-rice runs used TSD `UNK` (`regex.txt`),
   insert size 250, mismatch 2, no MAPQ gate. The harness runs R3 with
   `--tsd "..."`, `--min-mapq 1`, insert size 500.
3. Different pipeline. The harness calls the steps one by one without
   `--left/--right` on `align-genome`, so it skips mate-anchored genome
   alignment and RelocaTE2's full-read false-junction filter. `run-all` does
   both.

`--tsd "..."` routes to the fixed-pattern writer
(`InsertionFinder._write_event_start`), which has a non-RelocaTE2 branch from
`4b0624a` (2026-06-25): one-sided calls with more than one read get the
captured TSD instead of RelocaTE2's `insufficient_data`/`singleton` label, so
they pass the final filter. The default `UNK` path is not affected.

Test: `run-all` (rc1 clone env) on G_1 with R2's settings, job `30836949`
(intel, 17 min, 27 GB), output `results/release-validation/v0.2.0rc1/g1-runall/`:

```bash
relocaTE3 run-all -1 G_1_trim_R1.fastq.gz -2 G_1_trim_R2.fastq.gz \
  -T tests/data/TE_lib/mping.fa -g MSU_r7.fa -n G_1 -o g1-runall --threads 16 \
  --te-name mping --size 250 --mismatch 2 --repeatmasker MSU_r7.fa.out \
  --genotype --genotype-bam aln_input/G_1/G_1.sorted.markdup.cram
```

## Failures / issues found

- The README aligner table was stale and recommended `bowtie2` as a near-equal
  BLAT substitute (~2% loss). The October checkpoint shows every non-default
  combination finds about half as many insertions. Table replaced.
- README status quoted 194/200 at 90% precision; replaced with the measured
  196/200 at 1.000.
- `bcftools` (excision mode only) is not in the pixi environments. Documented.
- BLAT's academic/nonprofit-only license was not mentioned. Documented.
- The "blat is not on PATH" error told users `bowtie2` has the "closest
  accuracy" to BLAT; reworded to say every alternative finds far fewer
  insertions (`aligners.py`, message only; 315 tests pass).
- Real-rice attempt 1 (array `30216327`, 2026-10-21) failed on every sample in
  seconds: `sbatch --export=PATH` was reset by `run_relocate3.sh`'s login shell,
  and its pixi fallback used the default env, which has no blat. Fixed in
  `e2e9c56` (PATH set inside `--wrap`; fallback uses `-e blat`). Failed outputs
  moved to `results/release-validation/v0.2.0rc1/failed-30216327/`.
  Resubmitted 2026-10-26 as array `30803667`, report job `30803668`; cancelled
  while pending (epyc busy). Resubmitted 2026-10-26 15:10 on `intel` with the
  new `--partition` option: array `30832063`, report job `30832064`. All 10
  samples started and passed the BLAT check. Cancelled-attempt record in
  `results/release-validation/v0.2.0rc1/cancelled-30803667/`.
- The developer's local `blat` env lacked `seqtk` although the lock includes
