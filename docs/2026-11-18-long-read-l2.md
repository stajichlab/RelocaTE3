# Long-read L2: alignment, signatures, clustering

**Recorded:** 2026-11-18 15:20 PST
**Branch:** `feat/long-read-l2` (worktree `RelocaTE3-lr-l2`), gate run at `9bf00ef`
**Design / plan:** `plans/2026-11-17-long-read-l2-design.md`, `plans/2026-11-17-long-read-l2-plan.md`

## Purpose

First long-read code in RelocaTE3: align long reads to the genome, collect
insertion evidence per read, cluster it into candidate sites. No calls yet
(TE annotation and filters are L3).

## Status

**Gate: PASS** (SLURM job 32185663, 2 min 55 s for all eight read sets).
Site recall at 20x is 100 % on both ONT-HQ and HiFi.

## Commands

```bash
relocaTE3 lr-align      --sample S -o OUT --genome G.fa --read-type hifi --reads S.fastq.gz --threads 8
relocaTE3 lr-signatures --sample S -o OUT --bam OUT/S.lr.bam --read-type hifi
relocaTE3 lr-cluster    --sample S -o OUT --signatures OUT/S.signatures.tsv.gz

# The gate (from the repository root; needs the tests/data/longread_small link):
mkdir -p logs && sbatch validation/longread_l2/run_gate.slurm
```

## Gate results (`validation/longread_l2/output/gate.tsv`)

A truth site is found when a cluster lies within 50 bp of it. "min2" counts
only clusters supported by at least two reads. Control columns come from the
reference-only reads of the same platform and coverage.

| sample | found | recall | recall min2 | clusters | unmatched | control clusters | chance recall |
|---|---|---|---|---|---|---|---|
| ONT-HQ 5x | 198/200 | 0.990 | 0.935 | 210 | 12 | 1 | 0 |
| ONT-HQ 20x | 200/200 | 1.000 | 1.000 | 230 | 29 | 0 | 0 |
| HiFi 5x | 200/200 | 1.000 | 0.970 | 211 | 10 | 0 | 0 |
| HiFi 20x | 200/200 | 1.000 | 1.000 | 215 | 14 | 0 | 0 |

- **The two ONT-HQ 5x misses** (`mPing.Chr3.1043951`, `Dasheng.Chr3.1044853`,
  900 bp apart) have no reads at all over them in that sample: a coverage gap
  in the 5x simulation, not a detection failure.
- **Single-read sites at 5x** (13 ONT-HQ, 6 HiFi) are short inserts
  (145–1079 bp), each found by one read within 6 bp of truth.
- **Controls:** one cluster in all four controls (ONT-HQ 5x, a single-read
  clip at Chr3:334017); chance recall is 0 everywhere, so recall is not
  inflated by noise.
- **Unmatched clusters** (10–29 per sample) are what L3's filters address.
  The Task 7 review found they are mostly clip-only and single-read; some are
  a second cluster at a real site from a partial insert (a length split).

## Decisions (2026-11-17, maintainer)

- `--read-type` only on the new `lr-*` subcommands; `run-all` untouched until L3.
- DEL / Split-DEL deferred to L5.
- Gate: >= 95 % site recall at 20x on ONT-HQ and HiFi; 5x and false clusters reported only.
- `RelocaTE3.longread` subpackage, versioned TSV.gz intermediates; the only
  edit to existing code is a 2-line registration in `src/RelocaTE3/cli.py`.

## Found and fixed during review

- **SPLIT_INS pairing (Task 6):** pairing only consecutive alignments missed
  inserts whose TE body aligns to another TE copy on the same sequence and
  strand (12 of 200 sites lost all split-read support on ONT-HQ 20x). Fixed
  to "nearest collinear partner"; one SPLIT_INS per partner.
- **Clip attachment (Task 7):** was O(clips x sites); now bisection,
  20k + 20k in about 1 s.
- **Alignment errors (Task 8):** a `samtools sort` failure was reported as a
  minimap2 SIGPIPE; interrupts left child processes running. Both fixed.
- **Enum text, table ids (Tasks 1, 3):** enum `str()`/f-strings now give the
  value on every Python; ids with commas or empty ids are rejected.

## Known limits / follow-ups

- Chained INS merging can span matched bases (pieces >= 10 bp within 20 bp);
  never seen on the panel. Consider capping the merged span (L3).
- Length splitting can leave a second cluster at one site for a partial
  insert; L3/L4 should merge or annotate it.
- Reads with supplementary alignments keep one sequence in memory until the
  end of the BAM; estimated 1–2 GB for a whole rice genome at 30x.
- No read groups in `lr-align` output; needed before multi-sample BAMs (L3+).
- `samtools sort` memory and thread split are fixed defaults (768 MB/thread).
- CLR and R9 ONT are accepted but untested.
- The `tests/te_scatter_test.py::test_te_sam_header_keeps_a_complete_fai`
  fresh-checkout ordering issue on main is unrelated and still open.
