## Release check before the tag (Task 4)

Run on the release commit `<sha>` (the merge commit on `main`, or the PR
head if it merges without changes), from the main RelocaTE3 checkout.

`validation/release/fresh_clone_check.slurm <ref> [expected-version]`
compares the installed wheel's and sdist's `relocaTE3 --version` with
`expected-version` (default: `<ref>` minus a leading `v`). Before the tag,
versioningit describes the commit from the last tag, `v0.2.0rc2`, so a commit
`N` commits later reports `0.2.0rc2.postN+g<abbrev>`. Pass exactly that:

```bash
SHA=<release commit sha>
EXPECTED="$(git describe --tags --long "$SHA" | sed -E 's/^v(.*)-([0-9]+)-g([0-9a-f]+)$/\1.post\2+g\3/')"
echo "$EXPECTED"     # e.g. 0.2.0rc2.post90+g1a2b3c4
sbatch validation/release/fresh_clone_check.slurm "$SHA" "$EXPECTED"
```

Check: `results/release-validation/<sha>/summary.txt` ends with
`RESULT: PASS`.

Also before the tag:

```bash
sbatch tests/nextflow/parity_chr3.sh                         # pixi mode
NXF_EXTRA_PARAMS="--blat_chunk_reads 5000 --blat_chunks_per_task 3" \
  sbatch tests/nextflow/parity_chr3.sh                       # forced scatter
bash validation/release/submit_real_rice.sh "$SHA" --container-tag sha-<short>   # optional: Task 2 already ran it
```

After the tag, rerun the fresh-clone check on the tag; the expected version
is then the tag's:

```bash
sbatch validation/release/fresh_clone_check.slurm v0.3.0rc1 0.3.0rc1
```

## Maintainer release steps

1. Merge the PR into `main`.
2. Tag the merge commit and push the tag:
   ```bash
   git checkout main && git pull
   git tag -a v0.3.0rc1 -m "RelocaTE3 0.3.0rc1"
   git push origin v0.3.0rc1
   ```
3. Watch `.github/workflows/container.yml` on the tag: the image is built and
   checked, `containers/check_release.sh` must print `RELEASE CHECK: PASS`,
   then `ghcr.io/stajichlab/relocate3:0.3.0rc1` is pushed.
   `gh run list --workflow container.yml --branch v0.3.0rc1`, then
   `gh run watch <run id>`.
4. Create the GitHub release:
   ```bash
   gh release create v0.3.0rc1 --prerelease --title "RelocaTE3 0.3.0rc1" \
     --notes-file ../RelocaTE3/results/pr_messages/v0.3.0rc1-release-notes.md
   ```
5. Return `main` to a development version, on a new branch and PR:
   ```bash
   git checkout -b chore/post-release-0.3.0rc2.dev0 main
   bash scripts/post_release.sh 0.3.0rc2.dev0
   # run the tests it prints, commit, open a PR
   ```
6. Then (this session, follow-up PR recording the results here):
   ```bash
   sbatch containers/pull_and_check.sh --force-pull 0.3.0rc1        # PASS
   # from a scratch dir, Nextflow from the module:
   nextflow run stajichlab/RelocaTE3 -r v0.3.0rc1 -profile test,apptainer   # PASS
   sbatch validation/release/fresh_clone_check.slurm v0.3.0rc1 0.3.0rc1
   ```

## Post-release version convention

Decision: after tagging `vX`, `main` carries the next pre-release's dev
version and the `dev` image: after `v0.3.0rc1`, `manifest.version =
'0.3.0rc2.dev0'` and `container_tag = 'dev'`.

- The old convention `0.3.0dev` (= `0.3.0.dev0`) sorts *before* `0.3.0rc1` in
  PEP 440; `0.3.0rc2.dev0` sorts after it (and before `0.3.0rc2` or `0.3.0`).
  After a final `v0.3.0`, use `0.3.1.dev0` (or `0.4.0.dev0`).
- Nextflow accepts it: `nextflow config -flat -profile test,apptainer` on a
  copy after `post_release.sh` prints `manifest.version = '0.3.0rc2.dev0'`,
  `process.container = 'ghcr.io/stajichlab/relocate3:dev'`.
- Schema rule (`tests/nextflow_schema_test.py`): unchanged. It already keys on
  `Version.is_devrelease` (any `.devN` → `dev`, else the version itself).
  `tests/nextflow_schema_test.py`, `pipeline_docs_test.py` and
  `release_version_test.py` pass on a copy after `post_release.sh`.
- The Python package needs no edit: versioningit (`[tool.versioningit.vcs]`,
  default format) gives commits after the tag `0.3.0rc1.postN+g<sha>`,
  which sorts between `0.3.0rc1` and `0.3.0rc2.dev0`.
  `test_manifest_version_never_lags_the_package` holds (release part 0.3.0
  on both sides).
- `scripts/post_release.sh NEXT` refuses a NEXT that is not `.devN` or does
  not sort after the manifest, and a config that is not a consistent release;
  a rerun is a no-op. `tests/post_release_test.py` runs it on temp copies.
