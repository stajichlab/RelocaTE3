# Long-read L3: TE annotation, filters, first calls

**Recorded:** 2026-11-19 18:24 PST
**Branch:** `feat/long-read-l3` (worktree `RelocaTE3-lr-l3`), gate run at `2befe63`
**Design / plan:** `plans/2026-11-19-long-read-l3-design.md`, `plans/2026-11-19-long-read-l3-plan.md`

## Purpose

First long-read TE insertion calls: annotate every signature's inserted
sequence against the TE library (`lr-annotate`), vote a family per site,
merge same-family clusters, filter, and write calls (`lr-call`). Spanning
calls are gated; exact breakpoints, TSDs and clip-only placement are L4.

## Status

**Gate: PASS** (SLURM job 32235104, 2026-11-19, 1 min 37 s for all eight
read sets, 8 CPUs). At 20x, recall 0.98 and precision 1.00 on both ONT-HQ
and HiFi. Thresholds were not changed to reach this.

## Decisions (2026-11-19, maintainer)

- Gate: recall and precision >= 0.95 at 20x on ONT-HQ and HiFi, within
  50 bp with the correct family; strand, 5x and clip-only reported only.
- Two subcommands, `lr-annotate` (one minimap2 run per sample, per-read
  hit table) and `lr-call` (pure functions; refiltering does not rerun
  alignment).
- Minimum support: 2 reads for hifi / ont-hq, 3 for ont / clr.
- Identity defaults (hifi 0.85, ont-hq 0.80, ont / clr 0.70) are
  **provisional**: the panel's inserts are exact library copies, so they
  are untested on diverged copies.

## Known limits / follow-ups

- A nested insert shorter than about 150 bp is absorbed by minimap2
  (mGing inside Bajie).
- Composite / adjacent inserts (above) lose the smaller member; L4.
- Clip-only calls are written and annotated but not placed or scored
  until L4.
- No read groups in `lr-align` output.
- `lr-call` holds all TE-hit rows in memory and `lr-annotate` holds all
  query sequences; whole-genome ONT will hit this first.
- gzip readers are left open when `lr-call` fails early (harmless; the
  process exits).
- `lr-call` logs `calls by tier: ` with nothing after it when there are no
  calls (cosmetic; seen on the controls).
- Calls sit a few bp left of the truth position (HiFi 20x matches: mostly
  -3 to -12 bp, 0 at only 13 sites), likely minimap2 placing the insertion
  gap at the start of the duplicated TSD. Harmless inside the 50 bp window;
  L4's exact breakpoints should remove it.
- `lr-align` writes the sidecar after the BAM and index; if it dies in
  between, a rerun skips alignment and `lr-signatures` runs without the
  reference-id check. Write the sidecar first (L4).
- Output `.gz` files are not byte-identical across reruns (gzip header
  timestamp, from L2's `tables.py`); the unzipped content is identical
  (checked with minimap2 `-t 1` vs `-t 8`).
- CLR and R9 ONT are accepted but untested.
- The `tests/te_scatter_test.py::test_te_sam_header_keeps_a_complete_fai`
  fresh-checkout ordering issue on main is unrelated and still open.

## Where the plan and the code differ

The plan and design describe intent; these final details are in the code:
- Five filter reasons, not four: `few_te_reads` (fewer than 80% of reads
  have a TE hit) was added; the design was updated.
- The reference id is handed on in a sidecar `<sample>.lr.meta.tsv`
  (reference id, read type, genome), not a BAM `@CO` line (a linked user
  BAM cannot be edited); the design was updated.
- `lr-align --bam` checks an existing source sidecar (`x.lr.meta.tsv`
  beside the user's BAM) against the options before linking.
- The gate script's stale-output check compares each stage's output with
  the inputs it was really made from (calls against clusters, signatures
  and TE hits), not only the previous stage.
- `lr-call` also rejects TE-hit rows for signatures not in the signatures
  file.
- `CallParams` validates its ranges (support >= 1, merge window >= 0,
  identity and fractions in [0, 1]).
- `lr-annotate` rejects a library that is not FASTA and warns when no
  signature hits the library.
- The scorer computes `F1 = 2 tp / (n_truth + n_pass)` and finds candidates
  with a bisect window per sequence.
- Two extra columns beyond the design: `te_read_fraction` in `lr-calls`
  (the value checked by `few_te_reads`) and `query_length` in `lr-te-hits`
  (needed for insert TE coverage).
