## Task 3: MultiQC environment (2026-11-04 22:35)

**Decision:** the preferred path. MultiQC goes into the image's single
environment. No separate MultiQC container is used.

- `pixi.toml`:
  - new feature `report`: `multiqc = ">=1.35,<2"` (locked 1.35, bioconda
    `pyhdfd78af_2`, linux-64);
  - new environment `pipeline = ["blat", "report"]`;
  - `blat` and `pipeline` share `solve-group = "blat"`.
- The image is built from `pipeline` at `/opt/relocate3/.pixi/envs/pipeline`.
- `-profile pixi` defaults `--pixi_env` to `.pixi/envs/pipeline`, so every task,
  MULTIQC included, uses one environment.
- The `blat` env stays for `run-all` users. `parity_chr3.sh pixi` runs
  `run-all` from `blat` and the pipeline from `pipeline`.

**Why a shared solve-group.** Pixi solves an environment on its own unless it
shares a solve-group.
- Solved on its own, `pipeline` moved:
  - python from 3.12.13 to 3.13.18;
  - pysam from 0.24.0 to 0.24.1;
  - bowtie2's build;
  - about 50 libraries, including libgcc, libstdcxx, openssl, libcurl and perl.
- Pinning python, pysam and bowtie2 still left the libraries and pysam
  different.
- With the shared solve-group, every package in `blat` has the identical build
  in `pipeline`. MultiQC's stack (68 packages) is added on top.
- `tests/container_recipe_test.py::test_pipeline_env_contains_the_blat_env_exactly`
  checks this in the lock.

**Cost: the `blat` lock section changed.** The shared solve-group resolves
sphinx's pure-Python dependencies from conda instead of PyPI wheels:
- requests, jinja2, markupsafe 3.0.3 → 3.0.4, idna 3.18 → 3.20,
  certifi, urllib3 2.7 → 2.8, charset-normalizer;
- new: h2, hpack, hyperframe, brotli-python, pysocks, backports.zstd,
  cpython/python-gil 3.12.16 metapackages.

No tool, shared library, python or pysam changed. RelocaTE3 imports none of
these packages. `default` and `nf` lock sections are unchanged.
`pixi install --locked -e blat` works.
