## Task 4: per-sample stats (2026-11-04 22:57, commit 343253f)

**Decision:** a new small subcommand, `relocaTE3 sample-stats`
(`src/RelocaTE3/sample_stats.py`), not a `cohort --sample-stats` mode. The
cohort takes many characterized tables; the stats take one sample directory,
so a separate subcommand has a cleaner interface. It works on any run-all
sample dir, not only inside Nextflow.

```bash
relocaTE3 sample-stats -d <sample_dir> -n <id> [--target ALL] [--te-name repeat] -o <id>.stats_mqc.tsv
```

One MultiQC custom-content row (id `relocate3_sample_stats`, table
`relocate3_sample_stats_table`). It only counts lines.

| column | file | count |
|---|---|---|
| te_containing_reads | `te_containing/<id>.read_repeat_name.txt` | lines |
| flanking_reads | `flanking/<id>.*.flankingReads.fq` (same glob as run-all) | lines / 4 |
| nonref_raw / nonref_all / nonref_high_conf | `results/<target>.<te>.all_nonref_insert.{raw,all,high_conf}.txt` | lines |
| nonref_headline | `results/<target>.<te>.all_nonref_insert.gff` | lines |
| characterized | `...all_nonref_insert.characTErized.txt` | lines - 1 |
| reference | `results/<id>.all_ref_insert.txt` | lines - 1 |

**Headers, checked on M2 real-rice G_1 and in the writers:**
- The tier `.txt` files and the tier GFFs have no header (`insertions.write_tiers`).
- `characTErized.txt` and `all_ref_insert.txt` have one (`write_insertions_txt`).
- The headline tier exists only as `<stem>.gff`. The plain `<stem>.txt` is
  the unfiltered table and equals `raw`, so headline is counted from the GFF.
- The characterized and reference files are optional (genotyping, RepeatMasker).
  When one is missing, its column is left out, not set to 0. Any other
  missing file is an error, and so is a FASTQ whose line count is not a
  multiple of 4.

**G_1 (real data test, equal to the `wc -l` expectations):** 60604 TE reads;
raw 623, all 623, headline 623, high_conf 621, characterized 623, reference 13.

**MultiQC 1.35 merges the per-sample files** (same id) into one table. A
sample without a `characterized` column gets an empty cell
(`tests/multiqc_custom_content_test.py`).

**Process `RELOCATE3_SAMPLE_STATS`** (`modules/local/relocate3_sample_stats`):
- Stages the files in the run-all layout and runs `sample-stats -d .`.
- Its inputs are the TE_SEARCH, FIND_INSERTIONS, CHARACTERIZE and
  FIND_REFERENCE outputs. No existing module changed.
- **Not published.** The rows only feed MULTIQC. The merged table is in
  `multiqc/relocate3_report_data/multiqc_relocate3_sample_stats_table.txt`.
  It is not run with `--skip_multiqc`.

Red → green:
- pytest: `ModuleNotFoundError: RelocaTE3.sample_stats` → 14 passed.
- nf-test: `Script .../relocate3_sample_stats/main.nf not found` → 2 passed.

## Task 5: COHORT and MULTIQC in the workflow (2026-11-04 22:57, commit 1113bf3)

**Workflow:**
- `RELOCATE3_COHORT` (`modules/local/relocate3_cohort`) runs once after every
  CHARACTERIZE: `relocaTE3 cohort -i <id>=<table> ... -o .`.
  - The pairs are ordered with `toSortedList` by sample id, so `-resume` does
    not depend on which sample finishes first.
  - The tables all have the same name, so they are staged as `tables/<n>/`.
  - `NAME=PATH` keeps header-only samples.
  - If no sample was characterized, the sorted list is empty and COHORT
    does not run.
- `RELOCATE3_SAMPLE_STATS` runs once per sample, inside `ONE_SAMPLE`.
- `MULTIQC` (`modules/local/multiqc`) runs once at the end, unless
  `--skip_multiqc`:
  ```
  multiqc --no-ansi --force --config multiqc_config.yml [--title T] --comment C --filename relocate3_report.html .
  ```
  - It sets `export PYTHONNOUSERSITE=1`.
  - Its inputs are sorted by file name.

**Published:**
- `<outdir>/cohort/`: the 3 cohort files;
- `<outdir>/multiqc/`: `relocate3_report.html` and `relocate3_report_data/`;
- per-sample dirs: unchanged (the stub nf-test still asserts run-all's 33 files).

**Software versions in the report.** MultiQC 1.35 has a native "Software
versions" section, built from files matching `*_mqc_versions.yml`
(`search_patterns.yaml`, `core/software_versions.py`). Each file has the shape
`{group: {tool: version}}`, the shape of our `versions.yml`. nf-core's
template does the same (`nf_core_pipeline_software_mqc_versions.yml`).
- The workflow collects the versions a second time, as
  `relocate3_software_mqc_versions.yml`. Group names are reduced to the
  simple process name, e.g. `RELOCATE3_TE_SEARCH`.
- A `Workflow: {Nextflow, stajichlab/RelocaTE3}` entry is added, as nf-core does.
- `pipeline_info/software_versions.yml` keeps its fully qualified keys. It
  now also has COHORT, SAMPLE_STATS, MULTIQC and the `Workflow` entry
  (10 quoted entries in the stub test).
- MultiQC places this section last. Its table is in
  `relocate3_report_data/multiqc_software_versions.txt`, not in
  `multiqc_data.json`.

## Task 6 proposal: report on the real-rice M2 outputs

The M2 run used a different worktree and branch, so `-resume` from its work
dir would rerun every task. Instead, an sbatch job runs the two report
commands directly on the M2 sample dirs, with the same commands the
processes use:

```bash
REPO=$PWD; E=${REPO}/.pixi/envs/pipeline/bin; export PYTHONNOUSERSITE=1
M2=$(realpath ../RelocaTE3/results/nextflow-m2/nextflow-real-rice/dev)
OUT=${REPO}/results/nextflow-m3/real-rice-report
mkdir -p "${OUT}/mqc_in"
INPUTS=()
for d in "${M2}"/*/results/ALL.mping.all_nonref_insert.characTErized.txt; do
  s=$(basename "$(dirname "$(dirname "$d")")")
  "$E/relocaTE3" sample-stats -d "${M2}/${s}" -n "${s}" --te-name mping -o "${OUT}/mqc_in/${s}.stats_mqc.tsv"
  INPUTS+=("${s}=${d}")
done
"$E/relocaTE3" cohort -i "${INPUTS[@]}" -o "${OUT}/cohort"
cp "${OUT}/cohort/cohort.summary_mqc.tsv" "${OUT}/mqc_in/"
"$E/multiqc" --no-ansi --config "${REPO}/assets/multiqc_config.yml" \
  --filename relocate3_report.html -o "${OUT}/multiqc" "${OUT}/mqc_in"
```

Checked 2026-11-04 on a compute node, writing to scratch: exit 0, 10 samples
in the stats table (G_1 as in Task 4), MultiQC report written.

(The pipeline's `software_versions.yml` from M2 could be copied in as
`relocate3_software_mqc_versions.yml`, but its keys are fully qualified.)
